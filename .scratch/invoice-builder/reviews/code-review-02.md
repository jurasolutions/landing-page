## Standards

- *should fix*: `src/apps/invoice-builder/pdf.js:128-139` and `:159-178`. The header (business address and lines) and the "Bill to" block never check `room()` or add a page, so a long address is drawn below the page and lost. Reproduced on a scratch copy: a 3-item invoice whose business and customer addresses are 200 short lines each (within `LIMITS.address`, 400 characters) gives 350 text ops below the 64 pt bottom margin, the lowest at y = -4328. This breaks PRD §2 criterion 8 ("fits A4") and technical §6 ("a very long description does not run off the bottom" holds for the table, not for these blocks). It is inherited from the quote's `pdf.js:150-170`, which has the same gap, so the fix belongs here and not in the live quote. Either cap the printed lines of each block (wrap and stop with the rest moved to a new page), or wrap the left column through the same `room()` and `addPage()` checks the table uses. Add a pdf.test case with a 400-character, many-line address that asserts every non-footer op is at or above 64.
- *nit*: `src/apps/invoice-builder/pdf.js:149-153`. The label is drawn at `right - 150` and the value is right-aligned, so a long number overlaps its label. Reproduced: a 40-character number (`LIMITS.number`) starts at x = 294 while "Invoice no." ends at x = 442. Ordinary numbers (`INV-20261031-01`) fit. Wrap or shrink the value when it is wider than about 140 pt.
- *nit*: `src/apps/invoice-builder/pdf.js:43-47` and `InvoicePreview.jsx:23-27`. `discountLabel` and `discountCell` are the same function, written twice in new code (and a third time privately in the quote builder). Export one from a pure module, such as `totals-rows.js`, and use it in both, so the preview and the PDF cannot disagree about a discount cell, the same reason `invoiceTotalsRows` exists.
- *nit*: `src/apps/invoice-builder/InvoicePreview.jsx:64` and `:87`. `key={line}` repeats when two lines carry the same text (for example a contact name equal to the address line), which makes React warn and can drop a row on update. Use the index or a field name as the key.
- *nit*: `src/apps/invoice-builder/copy.test.js:115`. The sentence-case test lets "Invoice" (and "Item", "Page", "Edit", "Preview") through anywhere in a string, so "Download Invoice" would pass. Allow these words only as the first word, or only in the strings that need them.
- Blocked paths: none touched. The diff is confined to `src/apps/invoice-builder/`, `src/apps/registry.json` and `tests/invoice-builder-ui.test.js`. Nothing under `src/design-system/`, `dist/`, `.dev.vars`, `.env` or CI.
- Reuse: the diff imports `quoteTotals`, `formatCents`, `parseCents`, `displayDate`, `nextNumber`, `readBusiness`, `readGst`, `wrapText`, `fitLogo`, `toPrintable`, the P3 form parts, `_shared/storage.js`, `saveBlob`, `safeFilename`, `trackUsage` and the `qb-` layout, as `technical.md` §2 asks. The copied table loop in `pdf.js` is the duplication `technical.md` D3 accepted. No other reuse findings beyond the nit above.

## Spec

Each point the brief asked about:

- **Money maths through the imported calc, no copies, no float.** Met. `index.jsx:87` calls `quoteTotals` from `quote-builder/calc.js`. Every displayed amount is `formatCents` on BigInt cents (`totals-rows.js`, `pdf.js:225-229`, `InvoicePreview.jsx:118-130`). `offline.test.js` checks that `calc.js` is imported and not copied. `totals.test.js` covers no discount, line % and amount, overall discount, GST on and off, the half-cent ties and a sweep to 200.00 at four rates, plus 0.10 + 0.20 and 1.005.
- **"Invoice" title and no GST text with GST off.** Met. `copy.pdf.title(false)` is "Invoice" (`pdf.js:58`, `InvoicePreview.jsx:71`). The registration number prints only with GST on (`pdf.js:132`, `InvoicePreview.jsx:33`), and `invoiceTotalsRows` returns only Subtotal, Discount and Total with GST off. `pdf.test.js` "states no GST, rate or registration number, even with a registration number typed" and the matching preview and totals-rows tests pin it.
- **No Jura name on the PDF or in the metadata.** Met. Creator and producer are "pdf-lib" and the author is the business name (`pdf.js:61-64`). An empty business name prints nothing (D2, `pdf.js:121`). `pdf.test.js:136` checks every op and the metadata for both GST settings. `grep -il jura` on the built `pdf-*.js` chunks finds nothing.
- **Pagination and totals kept together.** Met for the items and totals: 40 lines on two pages with headings on each and no row split, and the totals on one page for 28 to 52 two-line rows, GST on and off, with and without a discount, with a wide logo. The header and "Bill to" gap is the *should fix* above.
- **Remember and blocked storage.** Met. Key `jura.invoice-builder.business.v1`. It keeps business, GST setting, payment details and the last number, and never customer, items, dates or notes. It writes only while ticked (`index.jsx:99-106`), forgets on untick (`:108-114`), falls back to no logo on a full quota (`remember.js:41`), and checks everything read back through `readBusiness` and `readGst`. Blocked storage renders the whole tool and shows the linked hint.
- **Usage counter.** Met. `open` comes from `AppShell` and `complete` is counted once per saved PDF, never for a blocked or failed download (`download.js:33-41`, `download.test.js`, `page.test.js` against the real registry).
- **Lazy pdf-lib.** Met. `loadPdf = () => import("./pdf.js")` and an idle warm-up. After `npm run build`, pdf-lib appears only in `pdf-*.js` and `PDFButton-*.js`. The invoice chunk `index-CjKqZEVK.js` has no `PDFDocument` and reaches `pdf-DFN45CaG.js` only through `import()`.
- **Labelled inputs and tap targets.** Met. Every field is a P3 part or a design-system control with a label. The overall-discount select uses `TAP` (`--tap-min`). The UI tests check that every input is named and that every button is a design-system button or meets the tap-target size.
- **Design-system-only styling.** Met. No new CSS. The tool uses `qb-` classes and `ds.js` components, and the only inline style is the logo's `aspectRatio`. The raw greys in `pdf.js:35-37` are on the visitor's own document, which carries their branding and not Jura's (PRD §4), and the file says so.
- **Registry entry.** Met. It is the PRD §5.3 entry with `added: "2026-10-31"` (D17).
- **copy.js carries every PRD §5.2 string word for word.** Met. Checked line by line against §5.2 (title, subtitle, privacy, Remember, six headings, 22 labels, six totals, empty items, zero quantity, three helpers, missing heading and field, six buttons, bad file, logo too big, and the three talk-to-us strings). `copy.test.js` pins each one, plus D6, D10, D12 and D4.
- **Voice of the new strings.** Checked by hand (D19; `jura-growth check` is not available on this run and stays with Ting Yu). "Your invoice", "Invoice builder view", "Line discount (%)", "Line discount (SGD)", "Overall discount (%)", "Overall discount (SGD)", "You can add up to {n} items to one invoice.", "Making your PDF…", "Invoice opened", "Quote opened", "Invoice preview", and the PDF labels "Invoice no.", "Due date", "Bill to", "Payment details" and "Notes" are all sentence case and plain, with no exclamation mark, emoji, buzzword, unevidenced figure or compliance claim. The other new keys (logo hint, blocked storage, "Percentage off", "Amount off", "Line total", errors, unsupported characters, PDF failed, "Tel", "Date", "All amounts in SGD") are the quote builder's words reused.
  - *nit*: `copy.js:146` "Please correct the figures marked in the form, then download your PDF again." No PDF was downloaded, so "again" misleads. Suggest "Please correct the figures marked in the form, then select Download PDF again." or "…then try again."
- **Seams for tickets 03 and 04.** Good. `GstFields` already sits in both places D4's order needs, `downloadInvoice` takes `missingFields` and checks it before figure errors (so a bad GST rate is listed as missing, which a test pins), and `messages` and `fileActions` are marked.
  - *nit* (for ticket 04): `index.jsx:154-159`. `openInvoice` doesn't reset `lastNumber` or `usedNumber`. An opened file whose number looks like `INV-YYYYMMDD-01` counts as a suggestion (`model.js:57-60` with `previous = ""`), so changing the date on an opened invoice renumbers it. Ticket 04 should decide whether an opened number is the visitor's (pass the opened number as `previous`, or mark it as edited).

## Security

No findings. There are no network calls besides `trackUsage` (`offline.test.js` stubs `fetch` and sees none). There is no `dangerouslySetInnerHTML`. The logo is shown only through `<img src={dataUrl}>`, so an SVG cannot run script, and the data URL is validated by `readLogo` on input and by `readBusiness` when read back from storage. Stored text is type-checked and cut to `INVOICE_LIMITS`. File names go through `safeFilename`. No secrets, auth, SQL or personal data leave the browser.

## UI (Web Interface Guidelines, `crew:web-design-review` on `index.jsx`, `InvoiceForm.jsx`, `InvoicePreview.jsx`, `GstFields.jsx`)

- Note: the guidelines' "Title Case for headings/buttons" contradicts the design system's sentence case. The design system wins, so this is not a finding.
- *nit*: `index.jsx:275`. `autoFocus` sits on "Start a new invoice", the action that clears the customer and items, so a stray Enter clears them. Focusing "Keep editing" is safer. (The quote builder's dialog does the same, so change both together or neither.)
- *nit*: `InvoiceForm.jsx:161-164`. The customer fields have no `autoComplete`, so a browser may offer the visitor's own name and email for their customer. `autoComplete="off"` (or a `section-customer` token) avoids that.
- *nit*: `InvoiceForm.jsx:78-82`. Removing an item is immediate, with no undo. That is acceptable for a single line, and the quote builder behaves the same.
- Passed: labelled controls, `aria-pressed` view switch, live regions present before messages, `aria-describedby` on hints, explicit image `width` and `height`, `…` in "Making your PDF…", tabular numerals and `overflow-wrap: anywhere` on preview text (from `quote-builder.css`), and reduced motion handled in the shared CSS.
