# Decisions after the spec reviews

The conductor settled the open points from `functional.md`, `technical.md` and
`test-strategy.md`. Nobody could be asked on this run, so each point takes a reviewer's
recommended answer. Where two reviews differed, the reason for the pick is given. These
decisions sit inside the approved PRD (A-0002) and don't change it. Tickets point here.

| # | Point | Decision | Source and reason |
|---|---|---|---|
| D1 | Imports and prefactors | As `technical.md` §2: import calc, model helpers, file readers, logo, WinAnsi and PDF geometry from `quote-builder/`. Prefactors P1 (export the quote file's section readers), P2 (`wrapText` to `pdf-text.js`) and P3 (form parts to `form-parts.jsx`) must not change the quote builder's behaviour | Tech lead |
| D2 | Empty business name | Never prints "Jura Solutions". The invoice builder doesn't use `effectiveQuote` or `DEFAULT_BUSINESS_NAME`. An empty name prints nothing, and with GST on it is a missing field | Functional B1, tech D4 |
| D3 | Suggested number | A new invoice starts with `INV-YYYYMMDD-01` typed into the field as real text, built from the invoice date. It follows the date until the visitor edits the number; after that, the number is theirs. A number the visitor clears stays empty, and with GST on it is listed as missing. "New invoice" on the same date suggests `-02`, then `-03` and so on (this session only; "Remember" also keeps the last number) | Functional B3 over tech §8: a printed placeholder could never be missing, so the required-field test for the number could never fail |
| D4 | Required fields (GST on only) | In form order: Business name, Address, GST registration number, Company or customer name, Customer address, Invoice number, Invoice date, GST rate (%) (empty, not a number, or above 100), and the items. Items: with no counted line, "Please add: Items"; for each counted line with no description, "Please add: Description for item N", linked to that line's description. "Counted" follows `calc.js` (`hasContent` and a quantity above zero). Each entry is a link to its input. Whitespace-only counts as missing. Update `CONTEXT.md` to match | Functional B4 and tech §5, merged. IRAS asks for the rate and for a description of what is charged |
| D5 | Totals rows | As `technical.md` §7. GST off: Subtotal and Discount only with a discount, then **Total**. GST on: Subtotal and Discount only with a discount, then Amount before GST, GST (r%), and **Amount with GST** as the final line, with no separate "Total" line. Preview and PDF both draw from `invoiceTotalsRows` | Tech §7, functional B2 and N1 |
| D6 | Quote saved with prices that include GST | It opens with prices as typed and GST on. A warning stays in the live region until the next file or New invoice: "This quote's prices include GST. Your invoice adds GST on top, so change each unit price to the amount before GST." The invoice model has no `inclusive`, so its maths always adds GST on top | All three reviews recommend it (tech Q1, functional B5, QA Q1). One line of copy beyond §5.2, checked by hand against the voice rules |
| D7 | What a quote file brings | As `technical.md` §3: customer, items, overall discount, notes (the quote builder's default note becomes empty), GST on and rate. The registration number comes from the quote only if the page has none. Business fields: the page's are kept, and **only empty ones** are filled from the quote (functional S3); the logo too, only when the page has none. The number, dates and payment details on the page stay | Functional S3 and tech §3. Filling empty fields only never overwrites, and it saves typing on the first visit |
| D8 | Invoice file | `{ format: "jura-invoice-builder", version: 1, savedAt, invoice }`, its own reader built on P1, newer versions refused, files over 3 MB refused. Both Open buttons accept both kinds of file. ADR 0005 from `technical.md` §9 | Tech D5, D6 |
| D9 | Opening a file over work on the page | Opens straight away with no question, as the quote builder does. A bad file changes nothing | Quote builder behaviour; fewer new strings. Functional S1 asked for a question first; not taken, because a saved file is the visitor's own and the quote builder doesn't ask |
| D10 | New invoice | Asks first, as the quote builder does: title and button "Start a new invoice", body "Your business details stay. The customer, items and notes are cleared.", cancel "Keep editing". Keeps business, GST setting and payment details. Clears customer, items, overall discount and notes. Dates reset to today, due date cleared, number suggested (D3) | Functional S2; copy mirrors the quote builder's dialog |
| D11 | Remember | Key `jura.invoice-builder.business.v1`. Keeps the "Your business" section with its logo, the GST setting (on, rate, registration number), the payment details and the last number. Never customer, items, dates or notes. Written only while ticked, deleted when unticked, through `_shared/storage.js`. If the quota is full, the details are kept without the logo | Tech D8 and functional S6. Payment details are the business's own and typed once |
| D12 | Due date before invoice date | Inline note under the due date, "The due date is before the invoice date.", and the PDF still downloads | Functional S5 |
| D13 | Numbers the totals can't read | As the quote builder: an inline error on the field, and "Download PDF" makes no file while one shows | Functional S4, following the existing tool |
| D14 | Seams for download and Remember | As `test-strategy.md`: `download.js` (`downloadInvoice` with build, save and track passed in) and `remember.js` | QA lead. Without them "creates no file" and "counts on completion" have no seam a test can reach |
| D15 | Usage counter | `open` comes from `AppShell`. `complete` is counted once per PDF saved. A saved invoice file and a blocked download are not counted | Tech §8, QA C14 |
| D16 | Default GST rate comment | `DEFAULT_GST_RATE` stays "9", with both IRAS URLs and "checked 2026-10-31 (PRD A-0002)" beside it. This build has no web access, so the build-day re-check is left to Ting Yu at G4 and noted in the comment | PRD §4 asks for a build-day check; it can't be done here |
| D17 | Registry `added` | `2026-10-31`, the build date. The release step corrects it to the deploy date | Tech §8 |
| D18 | Ticket split | Four tickets. 01 prefactor. 02 invoice to PDF with GST off. 03 tax invoice (GST on). 04 files and quote import. 03 and 04 are both blocked by 02 only, and run in parallel | Tech §12's fallback split, taken up front because ticket 02 as a whole wouldn't fit one developer run |
| D19 | Voice check | `jura-growth check` and the design system's README §3 aren't available in this repo (`src/design-system/` has no README). Copy is checked by hand against the voice rules quoted in `docs/agents/crew.md` and `README.md` "Brand rules", and the run is left to Ting Yu | No access on this run |
