- Every quote kept Subtotal, Discount, Total (SGD), Total before GST, Includes GST and "Prices include GST" **together on one page**, never split. For 20 and 21 lines the block ends page 1 and only the notes go to page 2. From 22 lines the whole block moves to page 2 (viewed at 22 and 46 lines). ## Exploratory charter findings

Charter: odd inputs, refresh, narrow phone, keyboard, saved-file edge cases, long documents.

1. **Odd rates** in inclusive mode: `9.50` prints "Includes GST (9.5%)"; `9,5` is read as 95 (the parser treats a comma as a thousands separator, so 48.72 is shown "included"); `9%`, `abc`, `-5`, `1e2` and full-width digits are invalid and count as 0%. These all match how exclusive mode already reads the rate, and the label shows the rate used.
2. **A blank or invalid rate does not block the PDF.** With the rate cleared, Download PDF still works and, in inclusive mode, prints "Includes GST (0%)" and "Prices include GST" with the red message only on the form. Exclusive mode behaves the same way today (it prints GST (0%)). Not a regression; the test strategy says a bad rate must error exactly as before. Worth a decision, see questions.
3. **Notes alone on page 2** at exactly 20 and 21 lines: existing layout on `main`, same page counts. Cosmetic.
4. **Phone preview**: in the totals block the rule under "Subtotal" stops short of the figure column (a gap between label and number). It appears with GST off too, so it is existing CSS, not from this change.
5. Switch off Add GST while inclusive is on, then re-open: the choice is kept in the file and the quote prints with no GST rows (as the test strategy expects).
6. Refresh without "Remember" loses the quote, as before. Two browser tabs were not tested in depth: storage is last write wins, and nothing in the change alters that.
